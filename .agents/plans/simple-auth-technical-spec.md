## Technical Specification: Go + React + SQLite Session Authentication## 1. Architecture Overview

- Frontend: React (Vite) managing UI state.
- Backend: Go (Golang) REST API managing business logic and security.
- Database: SQLite managing local, embedded storage.
- Auth Type: Stateful, cookie-based sessions (No JWTs). [1, 2, 3, 4]

---

## 2. Core Security Requirements

- Password Hashing: Passwords received in plaintext via HTTPS must be hashed on the Go backend using bcrypt (recommended cost: 12).
- Session Token: Cryptographically secure random string generated by the server via crypto/rand.
- Storage Mechanism: Tokens are sent to the frontend via an HTTP-only, Secure, SameSite=Strict cookie. React code cannot read or modify this cookie (XSS protection).
- CORS Configuration: Go backend must explicitly whitelist the React frontend domain (no wildcard *) and allow credentials (Access-Control-Allow-Credentials: true).
- React Fetch Configuration: All API calls from React (fetch or axios) must include the credentials flag (credentials: 'include' or withCredentials: true) to pass the cookie. [5, 6, 7, 8, 9]

---

## 3. Database Schema (SQLite)

CREATE TABLE users (
id TEXT PRIMARY KEY,
username TEXT UNIQUE NOT NULL,
password_hash TEXT NOT NULL,
created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE sessions (
id TEXT PRIMARY KEY, -- The session token string
user_id TEXT NOT NULL,
expires_at DATETIME NOT NULL,
FOREIGN KEY(user_id) REFERENCES users(id)
);

---

## 4. Backend Endpoints & Flow

- POST /api/register
- Accepts username and plaintext password.
  - Hashes password with bcrypt and saves user info to database. [10, 11]
- POST /api/login
- Accepts username and plaintext password.
  - Validates password using bcrypt.CompareHashAndPassword.
  - Generates a session token, stores it in SQLite with an expiration date, and sets the HTTP-only cookie. [12, 13, 14, 15]
- POST /api/logout
- Deletes the session record from SQLite and instructs the browser to clear the cookie.
- Auth Middleware (Interceptors)
- Wraps all protected endpoints.
  - Reads the session cookie, checks if it exists in SQLite, and ensures it has not expired.
  - Returns 401 Unauthorized immediately if invalid. [16]
